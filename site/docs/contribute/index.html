Contribute

Build with the pinned Rust toolchain, keep PRs focused, and run release tests before pushing.

Filing an issue

Search existing issues first. For bugs, use the report form and include your Openify version, Windows version, display scale and logs. For feature requests, describe the problem before proposing a solution. Report security problems through Privacy and security.

Logs are in %LOCALAPPDATA%\Openify: attach openify.log and any crash-<time>.txt report. For more detail:

PowerShell
$env:RUST_LOG="openify=debug"
.\target\release\openify.exe

Never post tokens or Spotify credentials.

Pull requests

  1. Open an issue before a substantial change. Read How it works.
  2. Branch from master, keep the PR focused, and run the checks below before pushing.
  3. Explain what changed, why and how you checked it. Include screenshots for UI changes and measurements against thresholds for performance changes.
  4. Add new UI text in both languages. Tests must use fixtures and temporary settings.
  5. Contributions are licensed under GPL-3.0-or-later.

What CI checks

CI runs on every PR and push to master.

JobChecks
Windowscargo build --release --locked, cargo test --release --locked, cargo fmt --check, cargo clippy --release --locked --all-targets -- -D warnings
Windows ARM64cargo build --release --locked --target aarch64-pc-windows-msvc
cargo-denyLicenses, bans and sources block failures. Advisories are checked but remain non-blocking.
Vendor drift./scripts/vendor-diff.ps1 -Summary reports differences from crates.io.

Openify ships an ARM64 installer; check native dependencies on that target too.

Conventions

  • Give new features their own gpui Entity; avoid adding fields to Shell.
  • The engine sends typed events and notice kinds; the UI supplies user-facing text.
  • Keep network requests, long disk work and blocking waits out of rendering.
  • Use tokens from src/ui/theme.rs and components from src/ui/components.rs. Tests in src/ui/design_rules.rs check raw design values and icon-button tooltips. See Design.
  • Keep decisions in pure, tested functions, as in queue.rs, recovery.rs and login.rs. Keep functions small; comments explain why.
  • Mark vendor changes with OPENIFY: comments, document them in the crate's OPENIFY.md, and run scripts/vendor-diff.ps1.
  • Reuse Spotify rate gates and caches. Tests use src/engine/fixtures or fake playback; settings tests use OPENIFY_SETTINGS_PATH with a temporary file.
  • Justify new dependencies and check license compatibility with cargo deny check licenses.

Internationalisation

Put English and Turkish UI text together in src/i18n/table.rs; missing translations cause compile errors. Use t!, tf! and tp! for plain, formatted and plural text, as documented in src/i18n.rs. The app name comes from src/brand.rs.

src/i18n/tests.rs checks placeholders, plurals, empty strings and raw Turkish text in source literals, with exceptions including comments and logs. Adding a language requires extending the table and language setting. Preview English or Turkish with OPENIFY_TEST_LANG=en|tr.

Building from source

Install Rust through rustup, Git, MSVC Build Tools with “Desktop development with C++” and the Windows SDK on Windows 10 or 11. Rustup uses rust-toolchain.toml. No .env or API key is needed.

PowerShell
git clone https://github.com/FurkanKY/Openify.git
cd Openify
cargo build --release --locked
.\target\release\openify.exe

The first build compiles gpui and its dependencies. Run a copy of the executable when testing; a running executable locks its build output. Use --target-dir for a separate build directory.

Running the tests

PowerShell
cargo test --release --locked
cargo clippy --release --locked --all-targets -- -D warnings
cargo fmt --check

Unit tests cover queue decisions, recovery, login, audio output, edits, i18n, settings and caches with fixtures or fake backends. Keep them off Spotify and real settings. The testing guide accepts only existing dependency warnings from vendor/librespot-core and proc-macro-error2.

Live-account tests, including friend activity, radio, credits and library writes, are #[ignore]d. Only the account owner should run them deliberately.

Test hooks

Setting OPENIFY_TEST_DISPLAY or OPENIFY_SETTINGS_PATH makes an app launch a test run with isolated cache and logs. Always point OPENIFY_SETTINGS_PATH at a temporary file to isolate settings too. It starts offline; OPENIFY_TEST_ONLINE=1 allows a live-account connection. Use temporary paths for overrides.

VariableEffect
OPENIFY_TEST_DISPLAY="w,h"Opens without focus on a secondary monitor, or the main monitor if there is only one. Closes after 15 minutes by default.
OPENIFY_SETTINGS_PATH=<file>Overrides %APPDATA%\Openify\settings.json.
OPENIFY_TEST_CACHE_DIR=<folder>Overrides the cache folder; test runs default to %TEMP%\openify-sandbox\cache.
OPENIFY_TEST_FAKE_PLAY=1Simulates playback without Spotify requests.
OPENIFY_TEST_OFFLINE=1Starts offline; empty caches show offline pages.
OPENIFY_TEST_LANG=en|trOverrides the interface language.
OPENIFY_TEST_THEME=light|darkOverrides the palette in test runs without saving the preference.
OPENIFY_TEST_VIEW=<page>Opens a page or panel after a delay, including now, home, settings, queue, help and search:<query>.
OPENIFY_TEST_SCALE=<0.5-4>With OPENIFY_TEST_DISPLAY, overrides scale. Use dot decimals, such as 1.25.
OPENIFY_LOG_DIR=<folder>Overrides log and crash-report storage; test runs default to %TEMP%\openify-sandbox\log.
OPENIFY_INSTANCE_ID=<name>Names the single-instance lock for parallel copies.
RUST_LOG=openify=debugLogs startup timings, audio device, format and queue targets.

JSON fixtures cover friend activity, credits, lyrics, radio and search. See docs/TESTING.md for all hooks and frame-time, memory and audio measurements. Measure with an executable copy and no real account; report results against thresholds.

gpui pitfalls

For gpui 0.2.2, keep these constraints in mind. More detail is in docs/TESTING.md.

Wheel capture
Capture handlers lack hit testing. Use smooth_scroll::wheel_zone; overlays use .occlude() to block scrolling or .block_mouse_except_scroll() to pass it through.
Text truncation
truncate() caches its first measurement; line_clamp crashes on multibyte characters. Use Line in src/ui/text.rs.
Flex text
A block wrapper can measure single-line text at zero width. Use .flex().min_w_0() and avoid max_w(relative(..)).
Focus
Root track_focus breaks window controls and resizing. Use a zero-size anchor; set tab order on the focus handle. Return focus after mouse clicks to avoid Enter/Space triggering another click.
Cached views
Notify each view that needs rebuilding; root notifications alone do not refresh children. Avoid nesting cached views and keep title-bar window_control_area hit areas outside them.
Shadows
Zero-blur shadows disappear; transparent elements get filled inside. Use a ring border.
Absolute elements
Set a corner such as top_0().left_0(); otherwise placement follows the previous sibling.
Images
Initial image loads notify only the first requesting view, requiring a bulk cover refresh.
Windows wheel
Wheel input uses ScrollDelta::Lines; touchpads send fractional lines.
