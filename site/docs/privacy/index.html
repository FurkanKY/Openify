Privacy and security

Openify runs on your machine and keeps its data there. This page lists what is stored where, which outside services the app talks to, and how to report a security problem.

No server, no telemetry

Openify has no server of its own. There is no account system, no analytics and no telemetry, so there is nothing for the app to send us.

The app talks to Spotify (it has to, to play your music) and to a handful of other services, only when a feature needs them. The full list is below.

What is stored and where

Everything lives under your Windows user profile. Nothing here is needed for correctness except the edit queue and your login.

WhatWhereNotes
Library cache, local play history, hidden songs%LOCALAPPDATA%\Openify\library.dbSQLite. The play history and hidden songs are yours and never leave the machine.
Page cache (artist, album, Home, Explore)%LOCALAPPDATA%\Openify\pages.dbOld entries show first and refresh in the background.
Covers and audio cache%LOCALAPPDATA%\Openify\covers, audioCovers are capped at 200 MB, the encrypted audio cache at 2 GB.
Logs and crash reports%LOCALAPPDATA%\Openify\openify.log, crash-<time>.txtThe last 5 crash reports are kept. Nothing is uploaded.
Settings%APPDATA%\Openify\settings.jsonPlain JSON.
Offline edit queue%APPDATA%\Openify\edits.dbLibrary edits made offline, saved before they are sent to Spotify.
Spotify sessionWindows Credential ManagerEntry Openify / spotify-session. Never written to a file.

To remove the cache, use the cache page in Settings or delete the folder. To remove the login, sign out in the app, or delete the entry under Windows Credentials in Credential Manager.

How sign-in works

Openify opens your browser and you sign in on Spotify's own page. Spotify then redirects back to a short-lived listener on 127.0.0.1:8898 on your computer, which hands the result to the app. Openify never sees your Spotify password.

The resulting session goes into Credential Manager. The app uses Spotify's own desktop client ID, a public constant in the source, because Spotify's internal services reject the IDs of ordinary developer apps. That is also why you need no API key to build the project.

Some Spotify features (friend activity, radio, track credits, lyrics translation) use endpoints Spotify does not document. They may stop working without notice.

Plays are not reported to Spotify

Openify's own playback sends no listening reports. The bundled librespot code and Openify's engine contain no call to Spotify's playback-reporting services, and Openify does not scrobble anywhere.

In practice, songs you play in Openify may not appear in Spotify's Recently played, in Wrapped, in play counts or in your friends' activity feed. This has not been checked on a live account for each of these. Playback you start on another device and transfer to Openify goes through Spotify Connect, and Spotify may count it.

Openify's own Recently played list and statistics are computed locally from your own play history.

Spotify Connect

Spotify Connect is on by default. Openify registers itself with your account as a device named Openify (<computer name>), so you can pick it in the Spotify app on your phone. It keeps the same device ID between runs and appears in your account's device list as a persistent device.

You can rename the device or turn Connect off in Settings. With it off, Openify registers no device.

Private session

A private session, switched on in the profile menu, stops Openify from recording recent plays and statistics locally for that session. A small icon in the title bar shows that it is on.

Discord Rich Presence

The code for showing your current song on Discord exists, but it is opt-in and the shipped build has it switched off. It needs a Discord application ID, and the constant that holds it is empty in the source. While it is empty there is no background worker and no Discord section in Settings.

If you build Openify yourself with your own application ID, the feature appears as a setting that stays off until you enable it. It talks only to the Discord desktop client on your own machine, over its local named pipe. It sends the title, artist, cover link and progress. Private sessions, pause, stop and turning the setting off clear the activity.

How updates work

Openify updates itself in the background with Velopack. By default it reads the update feed from this repository's GitHub Releases, downloads a new version and applies it the next time you open the app. You can point it elsewhere or switch it off with the OPENIFY_UPDATE_URL environment variable (a URL, or off).

If a new version fails to start twice, Openify returns to the last version that worked, from a copy kept on disk, so this also works offline. The rolled-back version is not downloaded again until a newer one is released.

The installer is not code-signed yet, so Windows SmartScreen may warn you the first time. Download only from the GitHub release page and check that the address is github.com/FurkanKY/Openify.

Reporting a vulnerability

Please do not open a public issue for a security problem. Use GitHub's private reporting instead: open the Security tab of the repository and choose Report a vulnerability. Only you and the maintainer see the advisory.

Include what the problem is and what an attacker could do with it, your Openify and Windows versions, and steps to reproduce it. Do not include Spotify credentials or tokens, and remove them from any log you attach.

Openify is a small project run by one person. You can expect an acknowledgement within a few days. Fixes are best-effort, and the report stays private until a fixed release is out.

Supported versions

VersionSecurity fixes
Latest releaseYes
Older releasesNo

Because the app updates itself, please update before you report. In scope are problems in Openify's own code and packaging: how it stores the session, handles the sign-in redirect, applies updates, or reads files and network responses. Problems in Spotify's services or in upstream projects such as librespot and gpui belong with those projects, though a report here is welcome if a dependency issue affects Openify.

Spotify's terms

Openify is an independent project and is not affiliated with, endorsed by or sponsored by Spotify AB. "Spotify" and its logo are trademarks of Spotify AB, used here only to say what Openify works with.

Openify talks to Spotify through the same unofficial, reverse-engineered interfaces as librespot. Using third-party clients can conflict with Spotify's terms of service, so you use Openify at your own risk. It does not download or save music, and it plays only on Premium accounts.

For the other known limits, such as no screen reader support, see the README. How the pieces fit together is in How it works.
