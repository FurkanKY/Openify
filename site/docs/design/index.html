Design system

Openify looks like a quiet listening room. The interface stays neutral and steps back, and the only color comes from the cover of the song that is playing.

The idea

Surfaces recede: neutral night in the dark theme, warm off-white in the light theme. The accent and the glow at the top of the window are derived from the current cover, and they fade to the next song's color over 0.8 seconds. The rest of the interface exists to carry that color without competing with it.

The priorities, in order, are plain, atmospheric, editorial. The plain base is a neutral background, tight but breathing rows and a floating player. The atmospheric layer is the cover color and glow, with covers everywhere. The editorial touch is bold Figtree on page titles. Components should feel calm and exact: almost invisible at rest, immediate and clear when touched. It is a player, and attention belongs to the music.

  • Color comes only from the cover. The interface has no accent of its own.
  • Depth comes from tonal layers. Shadows appear only on floating elements.
  • Every block aligns to one left edge: the shelf, the list header and the rows share the page margin, which is 32, 48 or 64 px depending on window width.
  • The library is a shelf of covers, and the player is a floating pill that carries the cover's light.
  • Every interactive element has five designed states: normal, hover, pressed, keyboard focus and disabled.

Text is never a fixed gray. It is the foreground color at different opacities: full for main text, 72% (dark) or 80% (light) for secondary text, 68% or 78% for labels, and 28% for disabled icons. That keeps text readable on top of cover tones and hover layers. Main text and surface pairs are held to WCAG AA, at least 4.5:1, by a unit test in both themes.

The theme setting is Dark, Light or System. A missing or unknown value means Dark. System follows the Windows app color mode live.

How the cover color is used

The accent (cover light) colors the playing row, the equalizer bars, the primary button, the focus ring and the selected shelf card. It is lightened as needed so it stays at least 4.5:1 against the background, and its hue is kept. The glow is a 460 px area at the top of the window, pre-mixed with the background rather than drawn as a transparent gradient. Its brightest point is capped, so even a yellow or pink cover leaves the room dark and the labels on top stay readable.

Typography

Figtree (embedded, OFL) is for titles. Segoe UI Variable Text, Windows' own interface font, is for everything else. Figtree renders blurry at 12 to 14 px, so it is never used below 18 px.

Spacing, shape and elevation

Spacing comes from one scale: 2, 4, 8, 12, 16, 24, 32, 48 and 64 px. Related items sit close and separate groups get a larger step. 2 px appears only between two lines of one item and in tight lists.

Shape is soft but tight: 2 px for thin bars, 4 px for small covers, 6 px for rows and menu items, 8 px for shelf covers, 12 px for floating panels such as menus and tooltips, and 20 px for the search surface. Icon buttons are circles. Primary buttons, filter chips and the title-bar search are full pills, as is the player.

Elevation is tonal: the background first, then translucent white layers on top. Hover is 6%, selected is 10% and pressed is 14%. The playing row takes the cover's tint instead of white, at 8%, 12%, 16% and 20% across its states. Shadows mean "temporary, above the content" and are used only for the search surface, menus, tooltips, the floating player pill and the slider handle. A docked side panel gets a quieter shadow because it sits in the same plane as the list.

Transitions come from a single token table in theme.rs: 140 ms for hover and press, 220 ms for page, panel and full-screen entry, 160 ms for exits, and 800 ms for cover color changes. Entrances slow down at the end, exits are shorter, and nothing makes input wait. With "reduce animations" on, everything is instant.

Named rules

One Light
The interface has no accent of its own. Color comes from the playing cover, or the default orange when there is none. Before anything plays, the room is dark.
Night Stays
However bright the cover, the glow has a ceiling, and the faintest label on top stays at 4.5:1 or better. A test checks this.
Tonal Layer
The same state looks the same everywhere: hover 6%, selected 10%, pressed 14%. A screen cannot invent its own opacity.
Six Sizes
The code has no font size outside the six roles above. Size and line height come only from type_role.
Steady Digits
Any number that changes (time, position, counter) uses tabular digits so it does not jitter.
Floating Shadow
Cards, rows and bars have no shadow. If an element has one, it floats above the content.
Single Color Logo
The logo, an O ring with a light dot sitting in a notch on its path, is one color: foreground or night. It never takes the cover color.

Do and don't

  • Do take spacing, radius and font size only from the scales in theme.rs.
  • Do show the same state with the same tonal layer.
  • Do add every new component to the component gallery (OPENIFY_GALLERY=1) with all five states.
  • Do pass cover-derived colors through ensure_contrast so they stay readable.
  • Do align a block to the shared left edge, page_margin.
  • Don't put a shadow on a row, card or bar.
  • Don't put an uppercase category label above a title. Put the type in the meta line.
  • Don't use a fixed gray for secondary text. Use a translucent foreground.
  • Don't add an accent color that does not come from the cover.
  • Don't use Figtree below 18 px.

How the rules are enforced

Design rules are checked by tests, not by review alone. src/ui/design_rules.rs holds count-based tests that must stay at zero. Spacing, radius, font size, shadow and color values may come only from src/ui/theme.rs, and every icon_button("...") must be followed by .tooltip(. A failing test means a raw value slipped in. Further tests there check that shadows appear only on floating elements and that Tab order follows the visual order.

Other tests protect specific promises: the contrast of text on both palettes, the brightness ceiling of the glow, and the number of song rows visible above the player at the smallest window sizes. The architecture page describes the wider test setup in how it is tested.
